# Community Queue V2

A single-streamer, server-authoritative Twitch community queue. Express serves the viewer, moderator, and OBS pages; Socket.IO sends live updates; SQLite keeps the queue across refreshes and server restarts.

## Install and run locally

Requirements: Node.js 22.5 or newer and npm. SQLite is provided by Node's built-in `node:sqlite` module, so no native addon or separate database installation is needed.

```sh
npm install
cp .env.example .env
npm start
```

Open `http://localhost:3000`. In development the moderator PIN defaults to `2468`. Set `MOD_PIN` in `.env` to choose another one. The SQLite database is created at `./data/queue.sqlite` by default; set `DB_PATH` to store it elsewhere. The `data` directory is ignored by Git.

For automatic server restarts while editing, use `npm run dev`.

## Moderator security

Set a private `MOD_PIN` environment variable before deployment. Set `SESSION_SECRET` to a long random value as well; production startup refuses to run without both values. Moderator sessions use an HTTP-only, signed cookie and expire after 12 hours. The mod API and mod-only Socket.IO state require a valid session. Use HTTPS in production.

## Deploy

### Render

This repository includes `render.yaml`. Create a new Render Blueprint from the repository, then provide `MOD_PIN` and `SESSION_SECRET` as secret environment values when prompted. The blueprint mounts a persistent disk at `/var/data` and stores SQLite at `/var/data/queue.sqlite`. A persistent disk is required to retain the queue across deploys/restarts.

Manual setup: create a Node web service, use `npm install` as the build command and `npm start` as the start command. Add a persistent disk mounted at `/var/data`; set `DB_PATH=/var/data/queue.sqlite`, `NODE_ENV=production`, `MOD_PIN`, and `SESSION_SECRET`.

### Railway

Create a Railway service from this project or its Git repository. Railway detects the included `Dockerfile`; alternatively use `npm install` and `npm start`. Attach a Railway Volume and mount it at `/data`, then set `DB_PATH=/data/queue.sqlite`, `NODE_ENV=production`, `MOD_PIN`, and `SESSION_SECRET`. The volume is needed because the container filesystem may be replaced during deploys.

The app listens on the hosting provider's `PORT` and binds to `0.0.0.0`.

## URLs

Replace the origin below with your deployed app URL:

- Viewers: `https://your-app.example/`
- Streamer/mod: `https://your-app.example/mod`
- OBS browser source: `https://your-app.example/display`

The OBS page is designed without controls or navigation. Add it as a browser source and set the source size to your intended scene resolution (for example 1920 × 1080).

## Queue behavior

The first database position is the current player. Joining is appended by the server in transaction order, and case-insensitive Twitch username uniqueness is enforced by SQLite. Finishing the current player promotes the next one. Mods can move waiting players, remove them, move the current player to the end, or clear the line after browser confirmation. Queue timestamps are generated by the server in UTC and shown in each viewer's local time.

## Notes

- This is intentionally a single shared queue, not a multi-tenant service.
- The tiny “DO NOT PRESS” button on the viewer page displays `dobbby_y Rulez` briefly.
- The local SQLite file should live on persistent storage in production. Do not use an ephemeral filesystem if you need restart persistence.
